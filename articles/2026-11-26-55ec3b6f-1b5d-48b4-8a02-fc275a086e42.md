# 固定资产推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:55ec3b6f-1b5d-48b4-8a02-fc275a086e42 -->

## 问题场景

固定资产状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/asset/stream', (msg) => {
  state.count += 1;
  document.querySelector('#asset-badge').textContent = state.count;
});
```

## 验证方法

手动断网再恢复，观察控制台是否在数秒内重建连接且状态不重复刷新。

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

结合团队现状，可以通过压测确认容量水位，避免资源被长期占用。

上线初期，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。

在跨团队协作时，建议在变更前留一份可回滚的快照，之后再考虑扩大适用范围。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

在多人协作的项目里，应当限定作用范围避免影响其他业务，使运维成本保持在合理区间。

结合历史事故记录，要把边界条件列成清单逐项确认，防止出现隐性回归。

从排障效率看，要明确各项资源的释放时机，并同步给相关方知会。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

在实际落地时，应确认依赖版本与运行环境一致，让容量规划更有依据。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使整体改动风险可控。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。
