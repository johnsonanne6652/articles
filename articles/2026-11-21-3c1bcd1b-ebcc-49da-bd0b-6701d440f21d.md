# 用分区表归档学员表的历史数据

<!-- content-workspace-job:3c1bcd1b-ebcc-49da-bd0b-6701d440f21d -->

## 问题场景

学员表积累了几亿行历史数据，DELETE 老数据要跑几个小时，还产生大量 WAL，删完之后磁盘空间也不释放。

## 实现步骤

按时间范围建分区，每个分区对应一个时间段。

```sql
CREATE TABLE students_202611 PARTITION OF students
FOR VALUES FROM ('2026-11-01') TO ('2026-12-01');
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
```

归档时把整个分区从主表摘下来，元数据操作，瞬间完成。

```sql
ALTER TABLE students DETACH PARTITION students_202601;
```

查分区列表确认挂载关系，摘除后主表查询自动跳过该段。

```sql
SELECT inhrelid::regclass
FROM pg_inherits WHERE inhparent = 'students'::regclass;
```

## 注意事项

分区键必须出现在查询条件里才能裁剪，否则照样扫全部分区；主表上的唯一索引必须包含分区键，这是常见的建表失败原因。

在多人协作的项目里，应当拆分步骤以便中途校验，让新人上手时少走弯路。

从排障效率看，应定期回顾相关监控指标，让容量规划更有依据。
