## 问题场景

节点模块从字典读配置，键名拼错或类型不对时要等运行到深处才报错，排查成本很高。

## 实现步骤

用 dataclass 声明字段与默认值，在 __post_init__ 里做范围校验。

```python
from dataclasses import dataclass, field

@dataclass
class Config:
    name: str = "node"
    limit: int = 16
    tags: list = field(default_factory=list)

    def __post_init__(self):
        if not 1 <= self.limit <= 100000:
            raise ValueError("limit 越界: %s" % self.limit)
```

从环境变量或文件读出原始字典后统一转换，非法值直接抛错并带上字段名。

```python
def parse(raw):
    return Config(name=raw.get("name", "node"),
                  limit=int(raw.get("limit", 16)),
                  tags=list(raw.get("tags", [])))
```

下游代码只接收已校验的对象，不再重复判断 None 或类型。

```python
c = parse({"limit": 16, "tags": ["cpu"]})
print(c.name, c.limit, len(c.tags))
try:
    parse({"limit": 0})
except ValueError as e:
    print("rejected", e)
```

## 验证方法

分别传入合法值与越界值，合法值应正常构造，越界值应抛出带字段名的异常。

## 注意事项

dataclass 默认不做类型检查，注释只是注释；可变默认值要用 field(default_factory=...)，直接写列表会共享同一个对象。

如果数据量继续增长，需要评估对现有调用方的影响面，确保线上行为始终可控。

对于刚接手的同学，应定期回顾相关监控指标，降低同类问题再次发生的概率。

从排障效率看，应定期回顾相关监控指标，防止出现隐性回归。

在资源受限的环境下，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

考虑到线上环境的差异，需要同时关注错误率与延迟两个指标，让新人上手时少走弯路。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确保线上行为始终可控。

在资源受限的环境下，建议在变更前留一份可回滚的快照，之后再考虑扩大适用范围。

从长期维护角度看，优先保证失败时能快速定位原因，以便快速定位瓶颈。

从可观测性角度，应确认依赖版本与运行环境一致，防止出现隐性回归。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

遇到复杂链路时，优先保证失败时能快速定位原因，确认指标平稳后再逐步放开。
