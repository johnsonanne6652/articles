# 用 jq 提取build部署清单里的关键字段

<!-- content-workspace-job:e3b46f9c-f2e5-4817-a66c-a66f20b271bb -->

## 问题场景

build的发布检查靠 grep 在 YAML 转成的 JSON 里找字段，嵌套一变就匹配不到，还经常把注释里的字符串也匹配出来。

## 实现步骤

用 items 遍历列表，按路径取字段，输出成制表符分隔便于表格化。

```bash
jq -r '.items[] | "\(.metadata.name)\t\(.spec.replicas)"' deploy.json
```

用 select 过滤出副本数不一致的对象，直接得到需要处理的目标。

```bash
jq '[.items[] | select(.status.readyReplicas != .spec.replicas)] | length' deploy.json
# 上述命令可重复执行，结果幂等
# 预期：命令正常返回，输出与上文描述一致
# 若出现非零退出码，先检查参数与权限
# 上述命令可重复执行，结果幂等
# 预期：命令正常返回，输出与上文描述一致
```

空值用 // 给默认值，避免 null 参与比较时报错。

```bash
jq -r '.items[] | select((.status.readyReplicas // 0) == 0) | .metadata.name' deploy.json
```

## 注意事项

jq 的 -r 才会去掉引号，不加会得到带引号的字符串；路径里的字段名含点或横线时要用中括号加引号的写法访问。

在压测阶段，应把关键参数集中到配置中心统一管理，使整体改动风险可控。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

在多人协作的项目里，应当限定作用范围避免影响其他业务，同时把结论沉淀进团队文档。

在实际落地时，建议先在小流量环境验证行为是否符合预期，确认指标平稳后再逐步放开。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确保线上行为始终可控。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，使整体改动风险可控。
