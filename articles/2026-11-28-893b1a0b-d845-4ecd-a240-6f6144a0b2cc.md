# 保单页面弹层关闭后把焦点还给触发按钮

<!-- content-workspace-job:893b1a0b-d845-4ecd-a240-6f6144a0b2cc -->

## 问题场景

保单弹层关闭后焦点回到页面顶部，键盘操作者需要重新 Tab 十几次才能回到原来的位置。

## 实现步骤

打开弹层前记录 document.activeElement 作为返回目标。

```javascript
let lastFocus = null;
function openDialog(dlg) {
  lastFocus = document.activeElement;
  dlg.hidden = false;
  const first = dlg.querySelector('button, [href], input');
  if (first) first.focus();
}
```

弹层内做焦点循环，Tab 到末尾时回到第一个可聚焦元素。

```javascript
function closeDialog(dlg) {
  dlg.hidden = true;
  if (lastFocus && document.contains(lastFocus)) lastFocus.focus();
  lastFocus = null;
}
```

关闭时先恢复焦点，再移除弹层节点，顺序颠倒会丢失目标。

```javascript
const dlg = document.querySelector('#policy-dialog');
openDialog(dlg);
closeDialog(dlg);
console.log('focus restored', document.activeElement.tagName, 680);
```

## 验证方法

用键盘打开再关闭弹层，焦点应回到触发按钮，连续按 Tab 不应跳出弹层。

## 注意事项

display:none 的元素不可聚焦，恢复焦点前要确保元素仍可见；aria-modal 需要配合实际焦点限制才有效。

从成本角度看，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

上线初期，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

对于刚接手的同学，应定期回顾相关监控指标，让排查路径更短。

在压测阶段，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

从长期维护角度看，先把最小可复现的用例固定下来，防止出现隐性回归。

上线初期，要把边界条件列成清单逐项确认，防止出现隐性回归。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。
