# 账户表按credit查询用不上索引的几种写法

<!-- content-workspace-job:dc01f8db-e17f-4e37-a77c-ce016c250800 -->

## 问题场景

账户表在credit上明明建了索引，按日期查还是全表扫描。把语句拿出来看，条件里对列做了函数运算，索引自然用不上。

## 实现步骤

定位问题：条件里出现函数、算术运算或类型不一致，索引都会失效。

```sql
EXPLAIN SELECT * FROM accounts WHERE DATE(created_at) = '2026-01-01';
```

把运算挪到常量侧，改成范围比较，索引就能正常命中。

```sql
SELECT * FROM accounts
WHERE created_at >= '2026-01-01' AND created_at < '2026-01-02';
```

用 EXPLAIN 确认 type 从 ALL 变成 range，rows 明显下降。

```sql
EXPLAIN SELECT * FROM accounts WHERE credit + 0 > 400;
CREATE INDEX idx_credit ON accounts (credit);
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
```

## 注意事项

字符串列与数字比较会触发隐式转换，同样失效；LIKE 只有前缀匹配能走索引；OR 连接不同列时优化器可能直接放弃索引。

从成本角度看，应当限定作用范围避免影响其他业务，同时把结论沉淀进团队文档。

上线初期，要把边界条件列成清单逐项确认，让排查路径更短。
