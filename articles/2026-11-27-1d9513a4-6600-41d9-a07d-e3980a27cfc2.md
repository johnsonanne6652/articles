# 变更单展示组件用自定义元素封装

<!-- content-workspace-job:1d9513a4-6600-41d9-a07d-e3980a27cfc2 -->

## 问题场景

变更单卡片在三个页面各写一份，改样式要同步三处，很容易漏改。

## 实现步骤

继承 HTMLElement 并挂到 shadow root，样式天然隔离。

```javascript
class ChangeCard extends HTMLElement {
  static get observedAttributes() { return ['title', 'value']; }
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }
}
```

声明 observedAttributes，属性变化时只更新对应节点。

```javascript
  render() {
    this.shadowRoot.innerHTML = `
      <style>.box{padding:10px;border:1px solid #ccc}</style>
      <div class="box"><b>${this.getAttribute('title') || ''}</b>
      <span>${this.getAttribute('value') || 0}</span></div>`;
  }
```

在 connectedCallback 里完成首次渲染，移除时解绑监听。

```javascript
customElements.define('change-card', ChangeCard);
const el = document.createElement('change-card');
el.setAttribute('value', '17');
document.body.appendChild(el);
```

## 注意事项

自定义元素名必须含连字符；shadow DOM 内的样式不会外泄，但外部也无法用普通选择器覆盖，需用 CSS 变量做定制入口。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

在跨团队协作时，建议在变更前留一份可回滚的快照，并保留回滚开关以便快速恢复。

遇到复杂链路时，优先保证失败时能快速定位原因，减少不必要的返工成本。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，同时把结论沉淀进团队文档。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，避免问题积累到难以收场。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

在资源受限的环境下，要避免在高峰期执行这类操作，同时把结论沉淀进团队文档。

如果数据量继续增长，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

在压测阶段，应把关键参数集中到配置中心统一管理，避免问题积累到难以收场。

上线初期，要把异常路径和正常路径分别覆盖一遍，以便快速定位瓶颈。
