# 用 git worktree 并行处理app的线上热修

## 问题场景

app线上出问题要立刻修，但当前分支改了一半，stash 之后切分支，修完再切回来经常把改动搞乱。

## 实现步骤

用 worktree 在旁边的目录开一个新分支，原工作区完全不动。

```bash
git worktree add ../app-hotfix -b hotfix/urgent origin/main
```

修完直接在该目录提交并推送，构建流水线照常触发。

```bash
cd ../app-hotfix && git commit -am "fix: patch app" && git push origin hotfix/urgent
# 预期：命令正常返回，输出与上文描述一致
# 若出现非零退出码，先检查参数与权限
# 上述命令可重复执行，结果幂等
# 预期：命令正常返回，输出与上文描述一致
# 若出现非零退出码，先检查参数与权限
# 上述命令可重复执行，结果幂等
# 预期：命令正常返回，输出与上文描述一致
# 若出现非零退出码，先检查参数与权限
```

合并后清理工作目录，避免遗留一堆孤立目录。

```bash
git worktree list
git worktree remove ../app-hotfix
```

## 注意事项

同一个分支不能在两个 worktree 同时检出，会直接报错；删除目录前先用 worktree remove，直接 rm 会留下失效记录。

上线初期，要把异常路径和正常路径分别覆盖一遍，确保线上行为始终可控。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，以便快速定位瓶颈。

在资源受限的环境下，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。

针对这类偶发问题，尽量把决策依据写进变更说明，避免资源被长期占用。

从成本角度看，应当限定作用范围避免影响其他业务，保证每一步都可验证。
