# 用 SSE 向订单页面推送实时状态

<!-- content-workspace-job:13215e23-4e7f-4f67-81ff-7eec5c8d3ac6 -->

## 问题场景

订单的进度页面用轮询，每秒一次，几百个用户同时打开就把接口打满，大部分请求还没有新数据。

## 实现步骤

服务端保持长连接，响应头声明事件流类型并关闭缓存。

```typescript
res.writeHead(200, {
  "Content-Type": "text/event-stream",
  "Cache-Control": "no-cache",
  Connection: "keep-alive",
});
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
```

有新数据就往连接里写一条事件，格式是 data 加空行。

```typescript
const timer = setInterval(() => {
  res.write(`data: ${JSON.stringify({ t: Date.now() })}\n\n`);
}, 1000);
```

客户端断开时清理定时器，否则连接关了还在往里写，服务端句柄泄漏。

```typescript
req.on("close", () => {
  clearInterval(timer);
  res.end();
});
```

## 注意事项

SSE 只支持服务端到客户端单向通信，需要双向就用 WebSocket；中间代理可能缓冲响应，要显式关闭缓冲并调大超时。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，减少不必要的返工成本。
