# 预算模块按路由拆分后再懒加载

<!-- content-workspace-job:60f4a237-5e44-4171-9578-ad2a7c0b6af3 -->

## 问题场景

预算后台首屏加载了全部页面代码，包体积接近三兆，弱网下白屏时间很长。

## 实现步骤

路由配置里用动态 import 替代静态引入，构建工具会自动拆包。

```javascript
const routes = [
  { path: '/', component: () => import('./Home.js') },
  { path: '/budget', component: () => import('./BudgetPage.js') },
];
```

给懒加载组件加加载态与错误兜底，避免等待期间没有任何反馈。

```javascript
async function navigate(path) {
  const hit = routes.find((r) => r.path === path) || routes[0];
  const mod = await hit.component();
  return mod.default ? mod.default() : mod.render();
}
```

## 注意事项

拆得太细会产生大量小请求，反而拖慢首屏；预加载策略要按真实路径设置，否则等于没拆。

从排障效率看，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

从成本角度看，应当限定作用范围避免影响其他业务，避免问题积累到难以收场。

从可观测性角度，应确认依赖版本与运行环境一致，防止出现隐性回归。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

在资源受限的环境下，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，避免问题积累到难以收场。

结合历史事故记录，要把边界条件列成清单逐项确认，降低同类问题再次发生的概率。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，便于横向对比不同方案的效果。
