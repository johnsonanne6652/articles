# 共享链接推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:818cc231-f902-488b-949f-cf865baba4da -->

## 问题场景

共享链接状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/share/stream', (msg) => {
  state.count += 1;
  document.querySelector('#share-badge').textContent = state.count;
});
```

手动断网再恢复，观察控制台是否在数秒内重建连接且状态不重复刷新。

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

在实际落地时，建议先在小流量环境验证行为是否符合预期，减少不必要的返工成本。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

在资源受限的环境下，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，避免问题积累到难以收场。

结合历史事故记录，要把边界条件列成清单逐项确认，降低同类问题再次发生的概率。
