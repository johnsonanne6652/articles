# 奖金页面弹层关闭后把焦点还给触发按钮

<!-- content-workspace-job:6d890300-af4a-4c27-9f2d-f031df58e4aa -->

## 问题场景

奖金弹层关闭后焦点回到页面顶部，键盘操作者需要重新 Tab 十几次才能回到原来的位置。

## 实现步骤

打开弹层前记录 document.activeElement 作为返回目标。

```javascript
let lastFocus = null;
function openDialog(dlg) {
  lastFocus = document.activeElement;
  dlg.hidden = false;
  const first = dlg.querySelector('button, [href], input');
  if (first) first.focus();
}
```

弹层内做焦点循环，Tab 到末尾时回到第一个可聚焦元素。

```javascript
function closeDialog(dlg) {
  dlg.hidden = true;
  if (lastFocus && document.contains(lastFocus)) lastFocus.focus();
  lastFocus = null;
}
```

关闭时先恢复焦点，再移除弹层节点，顺序颠倒会丢失目标。

```javascript
const dlg = document.querySelector('#bonus-dialog');
openDialog(dlg);
closeDialog(dlg);
console.log('focus restored', document.activeElement.tagName, 15);
```

用键盘打开再关闭弹层，焦点应回到触发按钮，连续按 Tab 不应跳出弹层。

## 注意事项

display:none 的元素不可聚焦，恢复焦点前要确保元素仍可见；aria-modal 需要配合实际焦点限制才有效。

结合团队现状，可以通过压测确认容量水位，便于横向对比不同方案的效果。

在迁移过程中，可以通过压测确认容量水位，避免资源被长期占用。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。

对于刚接手的同学，要明确各项资源的释放时机，确保线上行为始终可控。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

在跨团队协作时，要避免在高峰期执行这类操作，使运维成本保持在合理区间。

针对这类偶发问题，尽量把决策依据写进变更说明，便于横向对比不同方案的效果。

从长期维护角度看，先把最小可复现的用例固定下来，以便后续复盘有据可查。

遇到复杂链路时，先把最小可复现的用例固定下来，让排查路径更短。

结合历史事故记录，要把边界条件列成清单逐项确认，让容量规划更有依据。

针对这类偶发问题，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。
