## 问题场景

对托盘做分组聚合时，单进程跑满一个核，其余核空闲，整批处理时间被计算量卡住。

## 实现步骤

把数据按行区间切成若干块，每块交给一个子进程独立计算，避免共享内存竞争。

```python
def partial(args):
    path, start, end = args
    total = 0
    for line in read_slice(path, start, end):
        total += int(line.split(",")[-1])
    return total
```

子进程返回局部聚合结果，父进程只做加法合并，不在父子之间传原始数据。

```python
from multiprocessing import Pool

def scan(path, size):
    jobs = [(path, i, min(i + size, total_lines(path))) for i in range(0, total_lines(path), size)]
    with Pool(processes=4) as pool:
        return sum(pool.map(partial, jobs))
```

## 验证方法

用单进程结果作为基准，核对进程池输出的总量完全一致，再比较耗时。

## 注意事项

传给子进程的函数必须可序列化，闭包和 lambda 在 spawn 模式下会失败；Windows 上要放在 if __name__ 保护里。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，并保留回滚开关以便快速恢复。

在资源受限的环境下，建议在变更前留一份可回滚的快照，便于横向对比不同方案的效果。

如果数据量继续增长，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。
