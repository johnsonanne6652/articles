# 优惠券表单在提交前做集中校验并聚焦首个错误

## 问题场景

优惠券录入表单有十多个字段，校验分散在提交回调里，用户只看到顶部一个笼统提示。

## 实现步骤

用规则对象描述每个字段的必填、长度与格式要求。

```javascript
const rules = {
  name: (v) => (v.trim().length >= 2 ? '' : '名称至少 2 个字'),
  discount: (v) => (/^\d+$/.test(v) ? '' : '优惠券必须为数字'),
};
```

提交时遍历规则收集错误，把提示挂到对应字段下方。

```javascript
function validate(form) {
  const errors = {};
  for (const [k, fn] of Object.entries(rules)) {
    const msg = fn(form.elements[k].value);
    if (msg) errors[k] = msg;
  }
  return errors;
}
```

## 验证方法

只留一个字段为空提交，应看到该字段提示且光标落在该控件上；全部填对后应正常进入提交分支。

## 注意事项

异步校验要避免竞态，后发的请求可能先返回；聚焦前先确认元素仍然可见，隐藏字段无法获得焦点。

结合团队现状，可以通过日志补充上下文信息，使整体改动风险可控。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，减少不必要的返工成本。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

在压测阶段，应把关键参数集中到配置中心统一管理，保证每一步都可验证。

从排障效率看，应定期回顾相关监控指标，让容量规划更有依据。

如果数据量继续增长，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，之后再考虑扩大适用范围。

如果数据量继续增长，优先用工具把现状量化出来再动手，防止出现隐性回归。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。
